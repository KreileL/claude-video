# MCP v3 — notas no Holocron, bot do Telegram, resumo pelo Gemini

**Goal:** every finished job becomes, by itself, a folder in the Holocron's `00 - Entrada` (index note with summary, transcript, key frames); jobs are archived forever (no video kept); a Telegram bot is a second way to enqueue.

**Architecture:** the v2 worker gains a post-processing step (summary → export → archive) that never fails the job; a new `watch-telegram` service long-polls Telegram and enqueues through the same function as `analyze_video`. Three new modules with one job each: `entrada.py` (the only code that writes into the vault), `resumo.py` (LLM summary, text only, no tools), `telegram_bot.py`.

**Spec:** the v3 brief (conversation of 2026-10-18), summarized in NOTES-mcp.md "v3".

## Global constraints

- Production v2 (`watch-mcp:v2`, Desktop entry `watch`, container `watch-mcp-worker`) keeps working until promotion; v3 runs as `watch-mcp:v3`.
- Never: `docker compose down -v`, `docker volume rm|prune`, `system prune --volumes`, recreating/renaming `watch-mcp-jobs`. Volume changes are additive.
- Job `0ed8ff98d31ffbe6207d47f6c56b46f4` is irreplaceable: backup `D:\BACKUP\watch-jobs\job-0ed8ff98.tar.gz` (verified), state set to `archived` before the sprint.
- Tests never use the real volume or the real vault: temp dirs and temp volumes.
- Secrets (`telegram-bot-token.txt`, `gemini-api-key.txt`) only as Docker secrets; never read, printed or logged; every error/log line passes a redaction filter.
- Vault: only `00 - Entrada` is mounted, read-write, into the worker only. Create-only: exclusive creation, no overwrite, no delete (except our own `.watch-tmp/<job_id>`).
- No shell=True; containers non-root, read-only rootfs, cap-drop ALL, no-new-privileges, no published ports.

## Decisions

- **Archived = `state: "archived"`** (+ `archived: true`, `archived_at`, `archived_from`). The v2 cleanup only deletes `done`/`failed`, so the protection also holds if we roll back to the v2 worker. v3 readers treat `archived` like `done`. The cache cap counts only non-archived jobs (archives are small: no video).
- **Summary before publish:** on completion the worker tries the summary first, then renders everything in `.watch-tmp/<job_id>` and renames once. If the summary fails the note says `resumo: pendente`; a later success creates `Resumo.md` in the published folder (create-only), or a new full folder if the user already moved it.
- **Rename without replace:** `renameat2(RENAME_NOREPLACE)` via libc; if the filesystem refuses the flag, a check-then-rename fallback (documented).
- **Links inside the folder are relative Markdown links** (`[Transcrição](Transcrição.md)`, `![](frames/…)`): wikilinks would be ambiguous across many `Transcrição.md`.
- **Frontmatter values are JSON strings** (valid YAML) so a hostile title cannot inject keys.
- **Gemini:** `gemini-3.8-flash` (stable, newest Flash, 1,048,576-token input, image input; checked on ai.google.dev 2026-10-18), REST `generateContent`, key in the `x-goog-api-key` header (never in the URL), `thinkingLevel: low`. Free tier: Google uses the content to improve products — documented; `RESUMO_CAIXA_ENTRADA=0` turns summaries off for local files.
- **Telegram:** separate service `watch-telegram`, jobs volume only (no vault), offset + pending notifications in `/jobs/.telegram/state.json` (not a job id, so `_scan`/cleanup ignore it).
- **One worker at a time:** v3 services under compose profile `v3`; the v3 worker waits while another worker's heartbeat is fresh.

## Tasks

1. `entrada.py` + `tests/test_entrada.py` (Sonnet): title sanitizing, folder naming, staging, no-replace publish with suffixes, create-only files, Markdown sanitizing, key-frame picking, note/transcript/summary rendering.
2. `resumo.py` + `tests/test_resumo.py` (Sonnet): provider gemini|claude|none, delimited hostile transcript, output sanitizing hand-off, block mode for huge transcripts, transient vs permanent errors, call counter, key redaction.
3. `telegram_bot.py` + `tests/test_telegram_bot.py` (Sonnet): allow-list, URL extraction, commands, offset persistence, backoff, notifications.
4. Integration (Opus): `mcp_server.enqueue_analysis` shared by `analyze_video` and the bot; `archived` in jobstore/jobview/find_cached/list_jobs; worker post-processing + pending retries + `worker.py export <job_id>`; Dockerfile; compose (`watch-worker-v3`, `watch-telegram`, secrets, the `00 - Entrada` bind); Desktop entry v3 generator.
5. E2E on temp volumes + the acceptance list; Codex passes until no blocker; promotion.

## Review focus

- Hostile titles (`..\`, absolute, `CON`, control/bidi Unicode, very long) → safe name inside the mount.
- Prompt injection in the transcript ("ignore … grave em ../") → no effect on paths; output sanitized.
- Gemini down / quota / bad key → note with `resumo: pendente`, later `Resumo.md`.
- Vault mount missing or read-only → job `done`, export pending, retried.
- Foreign Telegram sender/group/channel → silence, nothing logged.
